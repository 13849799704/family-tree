# Spec Delta

## Purpose

保证仓库只跟踪源码与文档：依赖、打包产物、运行时族谱数据永不进入版本控制；构建配置不依赖
作者机器的绝对路径，任意 clone 都能构建；远端仓库在用户显式决定公开前保持私有。

## ADDED Requirements

### Requirement: 版本控制忽略清单覆盖全部非源码资产

仓库根的忽略清单 SHALL 覆盖全部非源码资产：第三方依赖、打包产物、运行时数据目录、
录入草稿目录、日志与备份/迁移临时文件。忽略清单的存在使常规开发工作流
（装依赖、跑应用、打包、录数据）之后 `git status` 只呈现源码与文档的变更，
贡献者无需记忆「哪些东西不能提交」。

#### Scenario: 全新 clone 后工作区干净

- **WHEN** 在任意机器上 clone 仓库并完成依赖安装
- **THEN** `git status` 不把 `node_modules/`、`dist/`、`数据/` 报告为未跟踪内容

#### Scenario: 四类非源码资产均被忽略

- **WHEN** 对 `数据/`、`数据底稿/`、`app/node_modules/`、`dist/` 执行忽略检查
- **THEN** 四个路径均被忽略清单命中

#### Scenario: 录入真实数据后不污染暂存区

- **WHEN** 用户在本地跑应用、录入真实族谱数据并触发每日备份
- **THEN** `git status` 不出现任何数据库、照片、快照或 `.bak` 文件

### Requirement: 构建输出路径可移植

构建配置 SHALL NOT 包含开发者机器的绝对路径；打包产物 SHALL 落在仓库内的相对位置，
使仓库 clone 到任何机器（含没有 D 盘的机器）后 `npm run dist` 都能成功执行。
相对化 SHALL NOT 改变作者本机的产物落点。

#### Scenario: 构建配置无绝对路径

- **WHEN** 检查构建配置中的输出目录声明
- **THEN** 其中不出现任何盘符绝对路径（如 `D:\...`）

#### Scenario: 相对路径解析到仓库内

- **WHEN** 构建配置声明的相对输出路径被解析
- **THEN** 产物落在仓库根目录的打包产物目录下，与源码树同源

#### Scenario: 本机产物落点不变

- **WHEN** 在作者本机执行打包
- **THEN** 产物仍落在原来的绝对位置，相对化不改变既有工作流

### Requirement: 远端仓库默认私有

远端仓库 SHALL 以私有可见性创建；转为公开 SHALL 只能由用户显式决策触发，
任何建仓、推送、日常提交操作 SHALL NOT 默认带入公开可见性。

#### Scenario: 远端创建时为私有

- **WHEN** 建仓并推送完成
- **THEN** 远端仓库的可见性为私有

#### Scenario: 转公开须显式决策

- **WHEN** 用户未作出转公开的决定
- **THEN** 仓库保持私有，不因任何常规操作（重新推送、加协作者、改设置）变为公开
