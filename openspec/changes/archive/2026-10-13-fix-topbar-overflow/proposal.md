# Proposal

## Why

窗口拖到最窄时（`minWidth: 1024`，也是用户能到达的最窄），左上角品牌区
「家族谱 / 称谓自动推导」会**逐字折行、纵向逃出 52px 的顶栏，盖住画布上的一整条横带**
（用户原话：「宽度不够会换行超出，其他是缩进然后被遮挡」）。

根因不是「宽度不够」，是**收缩优先级排错了**：

- `.brand` 在顶栏 flex 容器里**没有 `flex` 声明**（默认 `0 1 auto`，可收缩）；
- 而中文**可以逐字断行** → `.brand-text` 的 min-content 约等于**一个字宽**，
  于是它成为顶栏里**第三容易被牺牲**的项（排在 `.spacer`、`.view-switch` 之后）；
- 而它让位的方式（换行）恰好是整个顶栏里**唯一会纵向撑破**的失效模式
  —— 其余项让位只是变窄，最多触发省略号；
- `.topbar` 是固定高度且**没有 `overflow` 裁剪**，溢出的文字就直接画在邻居上面。

**这不是「某个更窄的宽度才触发」的问题。** 按真实 token（`--topbar-h: 52`、`--fs-lg: 15`、
`--fs-xs: 11`、`--sp-3: 12`…）算，1024 宽下余量只剩个位数像素 —— **在能到达的最窄处就已经坏了**。
所以验收标准不能写成「在 X px 以上不溢出」，只能是「**在 minWidth 下不越界**」。

此外还有一处**意图与实现互相矛盾**：`app.css:104` 的注释明写「顶栏横向空间紧张：谱名过长时截断」，
`.bc-name` 的省略号四件套（`overflow` + `text-overflow` + `white-space` + `max-width`）也齐了，
但外层 `.book-sw { flex: 0 0 auto }` 把这个能力锁死 —— 谱名在 flex 压力下**永远不可能**触发截断，
那套机制只在自己超过 `max-width: 116px` 时生效，跟窗口宽窄无关。**作者的意图从来没被实现过。**

## What Changes

- **D1　品牌区不再参与收缩**：`.brand { flex: 0 0 auto }` +
  `.brand-text { white-space: nowrap }`。品牌文字永远保持设计好的两行，
  纵向逃逸与遮挡从根上消失。
- **D2　谱名胶囊可以收缩**：`.book-sw { flex: 0 1 auto; min-width: 0 }` +
  `.bc-name { min-width: 0 }`。让实现追上 `app.css:104` 注释里已经声明的意图 ——
  挤压时谱名按既有的省略号机制截断（「母亲的家族」→「母亲的…」），
  而不是把压力全部顶给搜索框。压到底仍剩 ~93px（书图标 + 人数 + 下拉箭头），不会认不出是哪个谱。
- **D3　加回归断言**：沿 `tests/icon-size.html` 的骨架（iframe + 无头 Chrome + `waitFor` 轮询，
  已 3 连跑稳定），iframe 宽度设成 **1024**，验「顶栏无横向溢出 / 品牌区完全落在顶栏矩形内 /
  最坏组合仍不越界 / 谱名截断真的生效」。其中最坏组合由**主动构造**（灌长谱名 + 灌三位数人数），
  因为手验碰不到那个边界 —— 示例数据的谱名是「我的家族」，胶囊只要 ~154px，
  而余量告急发生在满格 232px 时。
- **强制负面验证**：这 4 条断言**必须先在未修复的 CSS 上跑一遍**，确认该红的红。
  红不了的断言是空断言，删掉而不是留着好看。（同一个陷阱在 `tests/icon-size.html`
  上出现过一次：「连线 N 条」在连线层被压扁时照样绿。）

**明确不做**：

- **不给 `.search` 加 `min-width: 0`** —— D1+D2 之后 1024 下余量有 231px，压根撞不到它
  自身 ~170px 的 input 固有宽地板。为一个当前没有场景的需求加规则，等于给后人留疑问。
  记作「若将来 `minWidth` 下调或顶栏再加控件，回来再看这一条」。
- **不整理 `.search` 与 `.spacer` 两个 `flex: 1` 的语义** —— `.search` 被 `max-width: 300`
  封顶，宽屏时剩余空间其实全被 `.spacer` 吃掉，让位永远「轮不到」按需分配。
  这是设计上的不清，不是这个 bug，另议。
- **不引入 `@media`（折叠副标题）** —— 项目目前**零宽度响应式规则**（唯一的 `@media`
  是 `tokens.css:133` 的 `prefers-reduced-motion`）。副标题「称谓自动推导」与窗口标题栏
  重复（`main.js:353` 就是「家族谱 · 称谓自动推导」），信息上冗余，值得单独议，但不该
  和这个 bug 捆在一起。
- 不动 `minWidth`、不动 JS、不动任何 `@media`。

## Capabilities

### New Capabilities

- `topbar-layout`: 顶栏在窗口最窄可达宽度（`minWidth`）下的布局不变量 ——
  品牌区不换行、不纵向越出顶栏、不遮挡画布；宽度不足时按「可截断者优先于固定项」的顺序让位。

### Modified Capabilities

无。现有 capability 为 `person-search`（搜索）与 `ui-icon-sizing`（图标尺寸），
均与顶栏布局无关，requirement 不变。

## Impact

| 位置 | 改动 |
|---|---|
| `app/src/styles/app.css` | `.brand` 加 `flex: 0 0 auto`；`.brand-text` 加 `white-space: nowrap`；`.book-sw` 改 `flex: 0 1 auto` + 加 `min-width: 0`；`.bc-name` 加 `min-width: 0`。**共 4 条声明，全在一个文件** |
| `app/tests/icon-size.html` | 新增第 6 组（顶栏布局断言），或另立 harness —— 二者验的都是「CSS 规则在真实 DOM 上是否按预期生效」，同源 |
| `app/package.json` | `version` 0.2.75 → 0.2.76 |
| `app/README.md` | §六 测试表（若新增断言）+ 更新日志 |
| `文档/overview.md` | §四 测试表（项数若变） |

- **不涉及** `app/index.html`：标记不动（D1/D2 全在 CSS）。
- **不涉及** `app/src/app.js` 与 `electron/main.js`：不动 `minWidth`、不动顶栏渲染。
- **依赖不变**：仍 `html2canvas` + `sql.js` 两个。
- **测试**：`npm test` 跑不到 CSS，本变更靠新增的布局断言 + 手验；
  风险集中在「余量算错」，故 D3 的最坏组合构造是刻意设计来打这个边界的。

### 一个前提值得单独记

**家族页固定只有 3 页**（`tests/run.js` 断言「固定三页：只出『母亲 / 妻子』两页」，
用户 2026-10-13 再次确认「家族页只会有三条，这是固定的」）。这给 `.view-switch` 封了个
约 277px 的顶 —— 是整个方案成立的前提。若将来页签能无限增长，顶栏这条路走不通，
修法必须换（那时该做的是把家族切换移出顶栏，而不是继续加断点）。
