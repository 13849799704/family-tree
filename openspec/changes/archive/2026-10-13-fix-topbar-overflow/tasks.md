## 3. D2　谱名胶囊可以收缩

- [x] 3.1 `app/src/styles/app.css`：`.book-sw` 由 `flex: 0 0 auto` 改为 `flex: 0 1 auto`
  并加 `min-width: 0`；`.bc-name` 加 `min-width: 0`。
  验证：harness 的断言 ④ 转绿，①②③ 仍绿（说明余量够，谱名让位没有牵连别人）。
  📌 **实施结果**：④ 转绿（`.bc-name` 116 → **99px**，被 flex 压到 max-width 之下）。
  ⚠️ **实测纠正了 design 里一处机制描述**：flex **不是「优先级分摊」，是按 base size
  比例分摊**。所以 D2 的效果不是「谱名独自承担压力」，而是「谱名**有资格**参与分摊」。
  证据：默认（短名「我的家族」）的 `bookSw=104` 反而比最坏（长名）的 `138` **更小** ——
  长名 base 更大、按比例分到的收缩也更多。变化量才看得出真相：
  `bookSw 156 → 104（-52）`、`viewSwitch 250 → 288（+38）`、`.search` 64 不变。
  **结果仍符合意图**（可截断的谱名让位，空间流向页签而非压扁搜索框），
  但「优先让位」是结果、不是机制 —— spec 里那句措辞描述的是结果，成立；
  design.md D2 的机制描述需要据此校正。
  ⚠️ 另：实测 `.search` 只有 **64px**（不是我按 `<input>` 固有宽估的 ~170px），
  真实余量比 design 算的 231px 更充裕 —— 靠算术估余量确实靠不住。
- [x] 3.2 核对 `.book-sw` 的地板：压到底应剩约 93px（书图标 15 + 计数 27 + 箭头 13 +
  padding 22），即省略号只出现在名字位置，不会出现「只剩一个图标认不出是哪个谱」。
  验证：把谱名灌到极长（远超 116px 上限）后，`.book-sw` 的 rect 宽度仍 ≥ 90px。

- [x] 4.3 **修一个我自己引入的回归**（D2 的副作用，必须先修）：`.book-chip` 溢出 `.book-sw`，

  机制：`.book-chip` 是 `inline-flex`（宽度走 shrink-to-fit），而 `.bc-name` 上的
  `white-space: nowrap` 让它的 min-content 等于整段谱名宽度；`.book-sw` 拿到

  用了注入长标签**之前**的 rect，已修正为注入之后再量）。
  ⚠️ **教训**：我原来的地板断言只查了 `.book-sw ≥ 90px`，**没查胶囊有没有溢出外层**，
  所以漏过了这个回归。加断言时要问「这个尺寸约束在**每一层**都成立吗」。
- [x] 4.4 家族页签可收缩：`.view-tab` 由 `flex: 0 0 auto` 改为 `flex: 0 1 auto`。

  也滚不过去。验证：三条页签断言全部转绿，`scrollWidth == clientWidth == 293`（需求不再超出），
  最大右侧超出 **0px**。
- [x] 4.5 谱名要有下限（用户选定方案 B）：`.bc-name { min-width: 0 → 3em }`。
  起因：修完 4.3 的溢出之后 `.bc-name` 真的开始让位、**让过头** —— 实测压成 **0px**，
  芯片里只剩书本图标 + 人数 + 箭头，完全认不出是哪个谱（`3em` 继承 `--fs-md`=13px，约 39px，
  露三个汉字）。
  ⚠️ **只加这一条不够 —— 修的过程中又暴露了第二层溢出**：
  加了 `min-width: 3em` 后胶囊变成**盒子内部装不下**（`scrollWidth 140 > clientWidth 120`，
  内容右溢 20px），而 `.view-switch` 在 DOM 里靠后、会盖住它 → 胶囊右端的人数与
  下拉箭头被页签遮住。**这一层 `getBoundingClientRect()` 完全查不到**，
  只有 `scrollWidth/clientWidth` 看得见 —— 断言因此补了一条。
  最终修法：`.book-sw` **去掉 `min-width: 0`**，让外层地板由内容决定
  （算出来的、不用手写数字）。实测 `bookSw 139/209 == bookChip 139/209`、
  `scrollWidth 207 ≤ clientWidth 207`、谱名 39/99px。
  验证：⑦ 由红（28px < 30）转绿（39px）；⑥ 两层（不溢出外层 / 内部装得下）全绿；
  页签三条仍全绿、`scrollWidth == clientWidth`。

## 8. v0.2.79　窄态「只显示姓名」的 Aa 图标太小

- [x] 8.1 **先量，别猜**。给 harness 加一组，量窄态下 `Aa` 字形与邻近**纯路径**图标的

  验证：拿到可比数字。
  📌 **「感觉很小」不是错觉**：`Aa` 可见字高 **5.2px**，而「添加成员」加号墨迹
  8.2px、「适应窗口」10.5px —— **只有一半**。

  实测给 10px 而实际字高只有 5.2px，**会让人误以为没问题**。
  最后用「em 尺寸 × 0.72（cap height 比例）」估字高，基准才取纯路径图标的 `getBBox`
  （那个是真墨迹）。
- [x] 8.2 根因：`Aa` 是全套图标里**唯一用 `<text>` 的**（路径描不出字形），
