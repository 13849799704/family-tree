## 三、🔴 必修（1 项）→ ✅ 已修复

### ~~世次推导值被写回数据库，固化成"人工覆盖值"~~ 【2026-09-18 修复】

> **状态：已修。** 修复方案与下面最初的建议不同 —— 改在 `model.js` 的**唯一写出出口**
> `serialize()` 上，而不是 `app.js`。理由见「实际修复方案」。
> 原问题描述保留，作为缺陷档案。

**位置**：`src/app.js:141`（`recompute` 里的 `withResolvedGen`）
　　　　`src/app.js:180`（`commit` 里的 `saveDataset`）
　　　　`src/core/model.js:383`（`effectiveGen` 显式优先）

**问题链路**：

```
recompute()   → state.dataset = withResolvedGen(dataset)   把每人 gen 抹成推导出的数字
commit()      → saveDataset(state.dataset)                 这份带 gen 的数据写进 people.gen 列
下次启动      → readDataset() 读出来 person.gen != null
effectiveGen()→ "显式优先" → 直接用存盘时的旧值，deriveGen 再也不参与
```

**我做了对照实验验证**（不是推测）：

```
场景：一个与主树不连通的旁支成员，给他加一个儿子
  · 从未存过盘：旁支某人 gen=1，其子 gen=0      ← 「最深后代落 gen 0」，符合设计
  · 存过盘之后：旁支某人 gen=0，其子 gen=-1     ← 被上次存盘的快照锁死

同一份关系，算出来的世次不一样。
```

**为什么必须修**：项目 README 第一条死规矩是「关系不存储，只存双亲指针 —— 改一处关系全树
自动更新」。世次是**派生**数据，把它持久化就等于绕过了这条规矩。后果是用户新增/修改父母关
系后，世次不跟着变（只会在体检 F8.3 里报一条"世次矛盾"，但树本身不会自动修正）。

**最初建议的修法**（改 `app.js`，约 5 行）：

**为什么不这么改**：`commit()` 只是写出路径之一。`boot()` 首次运行落库、导出备份
（`exportFile`）都会写数据，**每一处都得记得剔除**。漏一处就前功尽弃 ——
这种"靠调用方自觉"的约束迟早会被打破。

### ✅ 实际采用的修复方案

改在 `src/core/model.js`，**一处覆盖所有写出路径**：

1. **新增 `stripDerivedGen(dataset)`** —— 把推导出来的 `gen` 还原成 `null`，
   只留人工显式值，并删掉内部字段 `_genRaw`。对没推导过的数据集原样返回（幂等）。

2. **`withResolvedGen()` 改为先剥再推**：
   ```js
   export function withResolvedGen(dataset) {
     const base = stripDerivedGen(dataset);            // ← 先还原，保证输入干净
     const genMap = deriveGen(base);
     const people = base.people.map((p) => ({
       ...p,
       _genRaw: p.gen,                                  // 记住人工覆盖值
       gen: effectiveGen(p, genMap),                    // 生效值：显式优先，其次推导
     }));
     return { ...dataset, people };
   }
   ```
   先剥这一步很关键：它让 `deriveGen` 永远只看到**显式输入**，
   所以反复调用结果一致，不会「越推越偏」。

3. **`serialize()` 内部调用 `stripDerivedGen()`** —— 这是 `saveDataset`
   （SQLite / localStorage 两条路）和 `exportFile` 的**共同出口**，
   放在这里，调用方想忘都忘不掉。**`src/app.js` 一行没改。**

### 回归测试（`tests/run.js` 新增第 6 组，5 项）

| 测试 | 盯什么 |
|---|---|
| `serialize` 只写人工显式 gen | 推导值不得落盘，人工值必须保留 |
| `_genRaw` / `_orphans` 不泄漏 | 内部字段不得出现在导出文件里 |
| `withResolvedGen` 幂等 | 反复调用结果一致 |
| **★ 改关系后重新加载世次要跟着变** | **直接复现原缺陷：同一份关系，存没存过盘必须算出同一个世次** |
| 示例数据往返世次不漂移 | 真实数据级别的守卫 |

**测试有效性已验证**：我临时把 `serialize()` 里的剥离去掉跑了一遍，
第 4 条立刻红，报错信息与当初的对照实验完全对上：

```
同一份关系：没存过盘算出第 1 代，存过盘算出第 0 代 —— 世次被快照锁死了
1 !== 0
```

证明这个测试真能抓住该 bug，不是写了个永远绿的摆设。

## 四、🟡 建议修（7 项）

### 1. 缺 CSP —— 与「不联网承诺」有缝隙

`index.html` 全文没有 `Content-Security-Policy`。PRD §8 承诺"数据只存本地、不上传"，代码里
也确实没有网络请求，但**导入的 JSON 里 `avatar` / `photos` 字段可以是任意 URL**，渲染时
`<img src="${esc(p.avatar)}">` 会对外发起请求。`esc()` 只能防 XSS，防不住 SSRF 式的信息外泄
（对方服务器能拿到你的 IP 和访问时间）。

建议二选一：
- 在 `index.html` 加 `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; img-src 'self' data: blob:; script-src 'self'">`
- 或在主进程用 `session.defaultSession.webRequest.onHeadersReceived` 注入 CSP 响应头（Electron 下更可靠）

### 2. `paths.js` 的变量在声明前被使用（TDZ 隐患）

```js
// 第 52 行（函数内）      lastError = e;
// 第 61 行（模块顶层）    let lastError = null;
```

`resolveDataDir` 里给 `lastError` 赋值，但 `let` 声明在函数之后。目前能跑是因为模块求值完
才会被调用；一旦有人把它挪到顶层调用就会抛 `ReferenceError`，而且这个模块级变量会跨调用
残留上一次的错误。建议把声明提到函数前面，或改成函数内局部变量。

### 3. ✅ 已修复 —— 清空数据后，下次启动会自动灌回示例家族

`GenogramStore.clearAll()` 写空库 → `readDataset()` 里 `if (!people.length) return null`
→ `app.js` 的 `state.firstRun = !saved` 为真 → 走示例数据分支并**重新落库**。
用户以为清空了，重启发现 36 人又回来了。

**修法**：加 `meta.seeded` 标记区分两种「空」——

| 情况 | 判定 | 行为 |
|---|---|---|
| 全新库，从未写入 | `seeded` 不存在 | 载入示例家族（保留首次体验） |
| 用户主动清空过 | `seeded = 1` | 返回**空数据集**而非 null，保持为空 |

改动落在三处：`db.js` 写库时打标记 / 读库时区分；`store.js` 不再把「空数据集」吞成 null，
网页版清空的语义也从「删 localStorage key」改成「写一份空数据集」。

**顺带补的洞**：审查时这条还写着「UI 里没有 clear 入口，暂时触发不到」。但用户要录真实数据，
第一步必然是清掉示例 —— 所以顺手补了「文件 → 清空全部数据…」菜单项，二次确认放在渲染层
（只有那里知道有多少人、才能提示先导出备份）。

**验证**（不是只看代码）：真 Electron 连跑两次 —— 全新库启动 20 节点 → 清空 → 重启 **0 节点**，
且界面正确显示「还没有录入任何成员，从『添加成员』开始」。以前这个空状态引导一直存在，
只是被 bug 挡住，用户根本到不了。

### 4. `layout.js` 里的人物查找是 O(n²)

```js
const P = (id) => tree.people.find((p) => p.id === id);   // 第 60 行
```

`P()` 在 `isMain` / `kidsOf` / `place()` 递归里被反复调用，每次都是线性扫描。36 人无感，
但几百人的真实族谱会明显变慢。改成一个 `Map` 即可：

```js
const byId = new Map(tree.people.map((p) => [p.id, p]));
const P = (id) => byId.get(id);
```

### 6. `db.js` 用模板字符串拼 SQL

```js
const stmt = this.db.prepare(`SELECT COUNT(*) AS c FROM ${t}`);   // 第 371 行
```

目前 `t` 只有 `'people'` / `'relationships'` 两个硬编码值，安全。但这是"拼 SQL"的模式，将来
有人传个变量进来就是注入。建议加白名单：`if (!['people','relationships'].includes(t)) throw ...`。

顺带：`selectAll(sql, params)` 是公开方法且接受任意 SQL，注释已声明"只读用途"，建议补一句
运行时提示或直接标记为内部方法。

### 7. 配偶关系缺校验

`dialog.js` 的 `validate()` 只检查了「配偶不能是自己」。用户可以把**自己的父亲或子女**设为
配偶，数据能存进去，之后称谓推导会给出荒谬结果。

建议加一条：配偶不能是自己的直系血亲（`isDescendant` 函数现成，反向查一次即可）。

## 六、做得好的地方（值得保持）

- **XSS 防护做得很扎实**：15 处 `innerHTML`，我逐个检查过插值点，**每一处**都套了 `esc()`，
  没有一处裸插值。这在手写 DOM 的项目里不多见。
- **Electron 安全模型正确**：`contextIsolation: true` + `nodeIntegration: false`，preload 只
  暴露白名单 API。冒烟测试里专门断言了 `requireVisible: false` / `processVisible: false`。
- **写入有事务、落盘是原子的**：`BEGIN` + 清空重建 + `COMMIT`，落盘走 `.tmp` → `rename`。
  断电最多丢最后一次保存，不会写出半个损坏的库。
- **"未覆盖不猜"落实到位**：规则表匹配不到就输出关系描述 + `（关系待确认）`，绝不编造称谓。
  这是这个产品最该守的底线，守住了。
- **长幼判定优先用出生年**：`compareAge()` 明确处理了「三叔的长子 order=0、我是次子 order=1，
  但他 1995 生我 1992 生」的陷阱。我专门测了这一条，判对了。
- **畸形数据不崩**：8 种畸形输入全部被 `normalizeDataset` 挡住或降级，且体检会如实报出来，
  符合"只报不改"的设计原则。
