# Design

## Context

见 proposal.md - Why。此处只补做方案时需要的现状事实。

**顶栏的 10 个 flex 子项**（`index.html:17-111`），以及它们各自**能被压到多惨**：

| 项 | `flex` | min-width | 让位方式 | 让位的代价 |
|---|---|---|---|---|
| `.brand` | **无声明** → 默认 `0 1 auto` | `auto` → 中文可断行 → **≈1 字宽** | **换行** | **纵向撑破 52px，文字画到画布上** ★就是本变更的 bug |
| `.book-sw` | `0 0 auto` | auto | **零** | 谱名再长也不让 |
| `.view-switch` | 无声明 → `0 1 auto` | **`0`** + `overflow-x: auto` | 横向滚动 | 页签被静默裁切（`scrollbar-width: none` 把滚动条藏了） |
| `.search` | `1 1 0%` | `auto` → `<input>` 固有宽 **≈170px** | 变窄 | 有地板，压不下去 |
| `.spacer` | `1 1 0%` | auto (0) | 归零 | 无（纯占位） |
| `#callToggle` | 无声明 → `0 1 auto` | auto | 文字换行 | 「只显示姓名」换行 |
| `.zoom` | 无声明 → `0 1 auto` | `.zoom-val{min-width:46px}` | 几乎不让 | — |
| `fit` / `to-me` | 无声明 → `0 1 auto` | `.btn-icon` 写死 32 | 几乎不让 | — |
| `add` | 无声明 → `0 1 auto` | auto | 文字换行 | 「添加成员」换行 |

**机制**：flex 收缩时按各 item 的 **min-content** 分配压力。中文可逐字断行 →
文字类 item 的 min-content 极小 → 它们**最容易被牺牲**。而 `.brand` 的牺牲方式是
「换行」，是这张表里**唯一会纵向撑破布局**的失效模式（其余都是变窄或省略号）。
`.topbar` 固定 `--topbar-h: 52px` 且**无 `overflow`**（`app.css:59-66`），
所以溢出的文字直接画在 `z-index: 20` 的顶栏之上、盖住画布。

**宽度预算**（1024 宽，token 取自 `tokens.css`：`--topbar-h: 52`、`--fs-lg: 15`、
`--fs-xs: 11`、`--fs-sm: 12`、`--fs-md: 13`、`--sp-3: 12`、`--sp-4: 16`）：

```
可用 = 1024 - 32(padding) - 9x12(gaps) = 884

                        max-content   地板(min)   地板由谁决定
  .brand                    113         113      <- D1 后固定，不压
  .book-sw                  232          93      <- D2 后可压；书图标15+计数27+箭头13+padding22
  .zoom                     108         106      .zoom-val{min-width:46}
  只显示姓名                  96          48      padding24+圆点8+1字
  添加成员                   98          59      padding24+图标14+1字
  fit / to-me                64          64      .btn-icon 写死 32x2
  .search                   300         170      <input> 固有宽（D1/D2 都没动它）
  .view-switch              277           0      已有 min-width:0 + overflow-x:auto
  .spacer                     0           0      纯占位
                        ---------   ---------
                        1414         653
                        + gaps 108 + padding 32 -> 最低需求 793px

  1024 宽下余量 = 1024 - 793 = 231px
```

**一处意图与实现的矛盾**：`app.css:104` 的注释明写「顶栏横向空间紧张：谱名过长时截断」，
`.bc-name` 的省略号四件套也齐（`overflow`+`text-overflow`+`white-space`+`max-width:116px`），
但外层 `.book-sw { flex: 0 0 auto }`（`app.css:92`）把它锁死 —— 谱名在 flex 压力下
**永远不可能**触发截断，那套机制只在自己超过 `max-width: 116px` 时生效，与窗口宽窄无关。
**作者的意图从来没被实现过。**

**一个前提**（用户 2026-10-13 确认）：**家族页固定只有 3 页**（`tests/run.js` 亦断言
「固定三页：只出『母亲 / 妻子』两页」）。这给 `.view-switch` 封了约 277px 的顶。

## Goals / Non-Goals

**Goals:**

- 在**最小可达宽度**（`minWidth: 1024`）下，品牌区不折行、不纵向越出顶栏、不遮挡画布。
- 让宽度不足时的让位顺序符合语义：**可截断的项先让**，固定项与「只能换行」的项不动。
- 改动面收敛在 CSS，不碰标记、不碰 JS、不引入响应式规则。
- 把验收标准变成可执行的断言，并保证断言**红得了**。

**Non-Goals:**

- 不给 `.search` 加 `min-width: 0`（余量已够，见 D4）。
- 不整理 `.search` / `.spacer` 两个 `flex: 1` 的语义（设计不清，非本 bug）。
- 不引入 `@media`（折叠副标题），不改 `minWidth`。
- 不动家族页签数量与 `.view-switch` 的横向滚动机制。

## Decisions

### D1 — 品牌区固定，不参与收缩

`.brand { flex: 0 0 auto }` + `.brand-text { white-space: nowrap }`。

**理由**：`.brand-text` 折行是这张表里唯一**纵向撑破**的失效模式，且顶栏不裁剪，
越界必然显现为遮挡画布。让它可压缩，等于让最不该让位的项承担收缩。

**考虑过的替代**：

- *窄宽度下隐藏副标题（`@media` + `.brand-text small { display:none }`）*：
  空间多出 66px，但项目目前**零宽度响应式规则**（唯一的 `@media` 是
  `tokens.css:133` 的 `prefers-reduced-motion`），这是引入新模式；且副标题
  「称谓自动推导」与窗口标题栏重复（`main.js:353`），信息冗余值得单独议，
  但不该与本 bug 捆绑。
- *品牌区整体可省略（`min-width:0` + ellipsis）*：`small` 是 `display: block`，
  ellipsis 不跨 block，要额外处理；收益最低。

### D2 — 谱名胶囊可以收缩

`.book-sw { flex: 0 1 auto; min-width: 0 }` + `.bc-name { min-width: 0 }`。

**理由**：这不是新增能力，是**让实现追上 `app.css:104` 注释里已声明的意图**。
省略号四件套早已齐备，只缺「允许收缩」这一环。

**只做 D1 不做 D2 会怎样**：谱名满格 232 + 三位数人数时，
`brand(113) + search(170) + view-switch` 只剩 **0px 余量** —— 不是「够用」，是碰运气。
谱名再长一点就复发，且复发症状（页签被静默裁切、滚动条被 `scrollbar-width:none` 藏掉）
比原来的 brand 换行**更难排查**。所以 D2 不是可选项，是必需的兜底。

**地板校验**：`.book-sw` 压到底仍剩约 93px = 书图标 15 + 计数 27 + 下拉箭头 13 + padding 22。
省略号只出现在名字位置，**不会出现「只剩一个图标认不出是哪个谱」**。

**⚠️ 实施后的机制校正（实测推翻了自己的描述）**：
原以为 D2 的效果是「谱名独自承担压力」。**错的 —— flex 是按 base size 比例分摊，
不是按优先级分摊。** D2 的实际效果是「让谱名**有资格**参与分摊」。
证据：默认（短名「我的家族」）的 `bookSw=104` 反而比最坏（长名）的 `138` **更小** ——
长名 base 更大、按比例分到的收缩也更多。看变化量才清楚：

```
              D1 前   D1+D2 后   变化
  .book-sw      156  →   104    -52   谱名让出 52px
  .view-switch  250  →   288    +38   这些空间流向了页签
  .search        64  →    64      0   搜索框没被牵连
```

**结果仍符合意图**（可截断的谱名让位，空间流向页签，而不是把搜索框压扁或让页签被裁），
但「优先让位」是**结果**而非机制。`specs/topbar-layout` 里「被压缩后仍能以省略号呈现原意
的项优先收缩」这句描述的是可观察结果，成立。

**另一处算错的数**：上面预算表把 `.search` 的地板按 `<input>` 固有宽估成 ~170px，
**实测只有 64px**。所以真实余量比预算表算的 231px 更充裕 —— 这是「靠算术估余量靠不住」
的实证，`tests/topbar-layout.html` 顺手把它纠了出来。

### D3 — 回归断言，且强制负面验证

沿 `tests/icon-size.html` 的骨架（iframe 离屏 + 无头 Chrome + `waitFor` 轮询「应用真就绪」，
该 harness 已 3 连跑稳定）。iframe 宽度设成 **1024**。

**为什么不能只手验**：余量告急发生在「谱名满格 232px」，而示例数据的谱名是「我的家族」
→ 胶囊只要 ~154px。**手验根本碰不到那个边界**，会在「明明有问题」的情况下报通过。

**最坏组合用构造而非数据**：把谱名灌成长名（撑满 `max-width: 116px` 即最坏情况）+
把人数灌成三位数（`.bc-count` 是 `flex: 0 0 auto`，固定量），纯文本注入、不碰数据层。

**强制负面验证**：4 条断言**必须先在未修复的 CSS 上跑一遍**，该红的红。红不了的断言
是空断言，删掉而不是留着好看。**这条是从 `tests/icon-size.html` 身上学来的** ——
当初发现「连线 N 条 > 0」在连线层被压扁时照样 PASS，若不做负面验证就会把它当成有效断言。

**考虑过的替代**：并进 `tests/icon-size.html` 当第 6 组（两者验的都是「CSS 规则在真实 DOM
上是否按预期生效」，同源）vs 另立 harness。前者少一个文件、复用已验证的骨架；后者语义更清晰。
倾向前者，实施时按文件大小再定。

### D4 — 不给 `.search` 加 `min-width: 0`（明确的「不做」）

D1+D2 之后余量 231px，`.search` 压根撞不到自身 ≈170px 的 `<input>` 固有宽地板。

**这里有个容易搞反的点值得记**：`min-width: 0` 在 `.brand` 与 `.search` 上**方向相反** ——
`.brand-text` 的 min-content 极小（中文逐字断行），地板形同虚设，**禁止它压**才对；
而 `.search` 的地板来自 `<input>` 的固有宽，是真正卡住它的东西，**解除**才对。
同一个 `min-width: 0`，在两者上一个是解药一个是灾难。

为当前没有场景的需求加规则，等于给后人留「为什么加的」的疑问。**记作：若将来 `minWidth`
下调、或顶栏再加控件，回来再看这一条。**

### D5 — 顶栏两个 `flex: 1` 的语义问题不在这轮解决

`.search { flex: 1; max-width: 300px }` 与 `.spacer { flex: 1 }` 都在 grow。
因为 `.search` 被 `max-width: 300` 封顶，**宽屏时剩余空间实际全被 `.spacer` 吃掉** ——
搜索框永远停在 300，让位也永远「轮不到」按需分配。把 `.search` 改成 `flex: 0 1 300px`
（只缩不涨）、`.spacer` 独自 grow，语义会清楚很多。

这是设计上的不清，不是本 bug，且改动会牵连搜索框的宽屏视觉。**另议。**

## Risks / Trade-offs

- **[余量算错 → 最坏组合下复发]** → D3 的最坏组合断言就是为打这个边界设计的；
  实施时若发现余量比算的紧，把 `.book-sw` 的地板再往下压即可（`.bc-count` 已是 `0 0 auto`，
  没有更多可压空间，届时需重估）。
- **[断言是空断言（永远绿）]** → D3 的强制负面验证。红不了的断言直接删，不留。
- **[家族页数量若将来不固定，整个方案失效]** → `.view-switch` 失去 277px 上限，
  顶栏这条路走不通。缓解：本变更不动家族页机制（`tests/run.js` 有断言守住「固定三页」）；
  写进 README 与本 design 作为前提记录。若真要增长，正确的做法是**把家族切换移出顶栏**，
  而不是继续在顶栏里加断点。
- **[页签被静默裁切无从察觉]** → 预存问题：`.view-switch` 的 `scrollbar-width: none`
  把横向滚动条藏了。余量充足时不会发生（本变更后余量 231px），但若将来出控件挤压，
  用户会看到页签「少了」而找不到原因。本变更不修，只记录。
- **[将来换更长的品牌文案]** → `nowrap` 会让它向**右**溢出而非折行。但因为
  `flex: 0 0 auto`，它会把其余项整体挤小（有余量）而不是自己变形 —— 这是期望行为：
  品牌优先占据空间，别的项让位。
- **[Trade-off] 品牌固定后，谱名截断变得可见]** → 用户可能第一次看到自己的谱名被截成
  「母亲的…」。缓解：`.bc-name` 有 `max-width: 116px` 上限，且 `.book-chip` 的
  `title` 属性已带完整谱名（`app.js:308` 的 `title="${esc(it.label)}（${it.count} 人）"`），
  悬停可看全名。

## Migration Plan

无数据迁移、无配置开关、无依赖变更，改动即时生效。

回滚 = 删除 `app/src/styles/app.css` 里新增/修改的 4 条声明。四条互相独立
（`.brand`、`.brand-text`、`.book-sw`、`.bc-name`），删任何一条都不留半吊子状态：
少了 D1 会复发原 bug，少了 D2 只是余量归零。
