# Spec Delta

## Purpose

定义「给家人存照片、看照片」这项能力的对外行为：照片怎么进来、怎么展示、怎么设成头像、怎么跟着数据导出导入，以及各种异常情况下的降级表现。照片存在磁盘哪一层、走哪条传输通道，属于实现细节，不在本 spec 内。

## ADDED Requirements

### Requirement: 给成员添加照片
用户 SHALL 能为任意成员添加照片：通过系统文件选择对话框一次可多选，选中后照片进入该成员所属谱自己的照片目录，数据库记录其文件名。系统 MUST NOT 对单张照片设置大小上限——照片是家人好不容易收集来的家底，体积再大也要收得下。对无法解码的图片格式，系统 MUST 拒绝该文件并明确告知用户，不得把坏数据写进库。

#### Scenario: 一次多选添加
- **WHEN** 用户在成员详情面板点击「添加照片」，并在系统对话框中选中 3 张图片
- **THEN** 3 张照片全部入库，面板照片区显示它们，对应文件出现在该谱的照片目录里

#### Scenario: 拒绝无法解码的格式
- **WHEN** 用户选中的文件里有一个是无法解码的图片格式
- **THEN** 该文件被拒绝，用户收到明确提示；同一批里其他正常图片不受影响，照常入库

#### Scenario: 大文件不收上限
- **WHEN** 用户选中一张体积远超常见规格（如 20MB 以上）的合法照片
- **THEN** 该照片与普通照片一样正常入库，不因体积被拒

### Requirement: 面板照片区的展示与溢出提示
面板照片区 SHALL 最多同时展示 3 张缩略图；成员照片超过 3 张时，第 4 个位置 MUST 显示为「+N」角标（N 为超出的张数），点击后展开该成员的全部照片。没有照片的成员展示空槽与添加入口，与现状一致。

#### Scenario: 照片超出三张
- **WHEN** 某成员共有 7 张照片
- **THEN** 面板显示 3 张缩略图加一个「+4」角标；点击角标展开显示全部 7 张

#### Scenario: 照片不足三张
- **WHEN** 某成员只有 1 张照片
- **THEN** 面板显示 1 张缩略图和添加入口，不出现「+N」角标

### Requirement: 点击缩略图查看原图
用户 SHALL 能通过点击缩略图查看该照片的原图大图，并可关闭返回原界面。

#### Scenario: 灯箱看原图
- **WHEN** 用户点击一张照片缩略图
- **THEN** 以覆盖层形式展示该照片的原图，关闭后回到之前的界面，选中状态不丢失

### Requirement: 删除照片
用户 SHALL 能删除成员的任意一张照片；删除 MUST 同时移除磁盘文件与数据库引用，且操作前 MUST 有确认。系统 MUST 保证删除只作用于该谱照片目录内的文件——数据库引用中出现目录外路径时（历史脏数据或手工篡改），该路径 MUST 被拒绝删除。

#### Scenario: 正常删除一张照片
- **WHEN** 用户对一张照片选择删除并在确认对话框中确认
- **THEN** 该照片从面板消失，文件从照片目录移除，数据库该成员的照片引用不再包含它

#### Scenario: 拒绝删除目录外路径
- **WHEN** 数据库引用中包含一个指向照片目录之外的路径，用户尝试删除它
- **THEN** 系统拒绝删除该路径指向的文件，同一成员其他照片的删除不受影响

### Requirement: 将照片设为主头像
用户 SHALL 能将任意一张照片设为该成员的主头像；设置后，谱树节点与详情面板的头像 MUST 立即显示该照片。改设另一张照片时，主头像 MUST 跟随最新选择。

#### Scenario: 设置即生效
- **WHEN** 用户对一张照片选择「设为主头像」
- **THEN** 谱树中该成员节点与详情面板的头像立即变为该照片，无需重启或手动刷新

#### Scenario: 改设另一张
- **WHEN** 用户随后将同一成员的另一张照片设为主头像
- **THEN** 主头像变为新选的那张，旧设置被替换

### Requirement: 导出数据时可选择是否包含照片
导出 JSON 数据时，系统 SHALL 提供「包含照片」选项：选择包含时，照片数据 MUST 内联进导出的 JSON 文件使其自包含，且用户 MUST 事先被告知文件体积会显著增大；选择不包含时，JSON 只记录照片文件名，照片随谱文件夹一同迁移。

#### Scenario: 包含照片导出
- **WHEN** 用户选择「包含照片」并完成导出
- **THEN** 导出的 JSON 内嵌该谱全部被引用照片的数据，在另一环境导入后照片完整恢复

#### Scenario: 不含照片导出
- **WHEN** 用户以不含照片的方式导出
- **THEN** JSON 中只出现照片文件名，不含任何照片数据

### Requirement: 导入数据时自动恢复内联照片
导入 JSON 时，系统 SHALL 自动识别内联的照片数据并将其落盘到该谱的照片目录。对只记录文件名而磁盘上不存在的照片，系统 MUST 在导入结果中报告缺失数量，界面将这些照片降级展示，导入本身 MUST 成功。

#### Scenario: 内联照片自动恢复
- **WHEN** 用户导入一份内联了照片数据的 JSON
- **THEN** 照片落盘到当前谱的照片目录，各成员的照片正常显示

#### Scenario: 缺失照片报数
- **WHEN** 导入的 JSON 引用了 3 个磁盘上不存在的照片文件
- **THEN** 导入成功，导入结果提示缺失数量，面板中对应位置显示为空槽

### Requirement: 照片文件缺失时的界面降级
界面引用一个磁盘上不存在的照片文件时，系统 SHALL 将其显示为空槽（与没有照片一致），MUST NOT 显示破图或崩溃；该成员其他的照片操作（添加、删除其他照片）MUST 保持可用。

#### Scenario: 文件被外部删除
- **WHEN** 某成员的照片文件在系统外被删除（如在资源管理器中手动删除）
- **THEN** 面板对应位置显示为空槽，用户仍可为该成员添加新照片、删除其他照片

### Requirement: 不具备本地文件能力时不提供照片入口
运行环境不提供本地文件桥时（如网页版），系统 SHALL NOT 渲染照片添加入口，照片区展示与现状一致；谱数据功能 MUST 不受影响。

#### Scenario: 无桥环境的面板
- **WHEN** 在没有本地文件桥的环境中打开成员详情面板
- **THEN** 不显示「添加照片」按钮，面板其余功能与数据操作正常
