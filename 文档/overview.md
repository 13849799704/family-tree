## 一、最近几轮做了什么

### 第二轮：桌面化（从「网页版」转成「PC 桌面应用」）

上一轮交付的是浏览器网页版（数据存 localStorage）。你指出要的不是网页，是**只用本地数据库保存的 PC 端应用** —— 于是做了桌面化改造。

| 层 | 内容 |
|---|---|
| **桌面壳** | Electron 44（主进程 + preload 桥 + 渲染进程，contextIsolation 隔离） |
| **本地数据库** | SQLite（`sql.js` 的 WASM 版），落盘成标准 `.db` 文件，任何 SQLite 工具都能打开 |
| 数据位置 | `D:\族谱pc端项目\数据\genogram.db`（**不在应用目录里**，卸载重装不丢数据） |
| 安全模型 | 页面里没有 `require` / `fs` / `process`；能力经 preload 白名单暴露 |
| 菜单 | 原生菜单（文件 / 视图 / 帮助），导入导出走系统「打开/另存为」对话框 |
| **存储层可插拔** | `store.js` 认 preload 桥就走 SQLite，否则退回浏览器本地存储 —— **core / ui 一行没白写** |

### 第四轮：代码审查 + 两处缺陷修复

通读全部代码后发现 **1 个必修 + 4 个建议**，你选了「先修必修的」，于是修掉两处会真正坑到数据的缺陷：

| # | 缺陷 | 为什么必修 | 修法 |
|---|---|---|---|
| 🔴 1 | **世次推导值被写回数据库固化** | `recompute()` 把推导出的 `gen` 抹成了真实值 → 存盘 → 重开后 `gen != null` → 推导再也不参与。**同一份关系，存过盘和没存过盘世次不一样**，直接违反硬约束 1 | 在 `model.js` 加 `stripDerivedGen()`：`serialize()`（落盘/导出的唯一出口）自动剥离，`withResolvedGen()` 先剥再推保证幂等 |
| 🟡 2 | 清空数据后重启，示例家族自己回来了 | `readDataset()` 空库返回 `null` → 被当成首次运行 → 回灌示例。用户根本到不了空状态 | 加 `META_SEEDED` 标记区分「全新库」和「用户主动清空」；文件菜单补「清空全部数据」入口 |

两处都补了回归测试，并且**故意把修复退掉重跑一次，确认新测试真的会红** —— 不会红的回归等于没有。
（2026-09-18 那一轮：core 53→**58**、存储 34→**36**；截至 2026-10-10 已分别增至 **94** / **37**）
完整 5 条建议见 `代码审查报告.md`。

### 第五轮：确认「包里的代码 == 现在的源码」

打包是某个时间点的快照，之后源码再改（或像这次误删后从 asar 恢复），**安装包就和源码脱节了**，而只看文件在不在、只看大小都验不出来。
所以新增 `app/scripts/verify-asar.js`：逐文件 sha256 比对，业务代码任一字节不同就退出码 1。

```bash
cd app && node scripts/verify-asar.js
# ✅ 打包产物与当前源码一致（业务代码字节级相同）
```

当前结论：**21 个业务文件字节级完全一致**，`package.json` 的差异是 electron-builder 打包时重写导致的（属预期，脚本会单独列出并忽略）。

## 二、三条硬约束（贯穿全部代码）

1. **关系不存储，只存双亲指针。** 称呼永远实时算 —— 改一处关系，全树称谓自动更新。这是与传统族谱软件的根本区别。
2. **未覆盖不猜。** 规则表匹配不到就输出「关系描述」兜底，绝不编造称呼。
3. **core 层无 DOM。** `src/core/*` 不碰 `document`，所以布局和称谓能在 Node 里直接单测。

## 三、几个值得记下的技术决策

### 为什么用 sql.js 而不是 better-sqlite3

`better-sqlite3` 是原生模块，要按 Electron 的 ABI 重编译，本机没有 VS Build Tools 会直接卡死。
`sql.js` 把 SQLite 编译成 WASM，**零编译**，代价是整库常驻内存 —— 族谱这个量级（几百人 / 几 MB）完全无感。

将来要换回 better-sqlite3：**只改 `electron/db.js` 一个文件**，表结构、`store.js`、UI 全都不用动。

### 写入的两条硬保证

1. **事务**：每次保存是「清空 + 重建」放一个 `BEGIN/COMMIT` 里。族谱量级下比逐行 diff 简单得多，而且天然一致 —— 不会出现「人删了、关系还在」的半截状态。
2. **原子落盘**：先写 `.tmp` 再 `rename` 覆盖。同卷 rename 是原子的，断电最多丢最后一次保存，**不会写出半个损坏的库**。

### 备份

- `genogram.db.bak` —— 上次退出时的状态
- `backups\genogram-YYYYMMDD.db` —— 每天启动一份快照，保留最近 30 份
- **备份 = 直接拷贝 `D:\族谱pc端项目\数据\` 整个文件夹**

### SQL 关键字规避

`order` → `order_no`、`from` → `from_date`、`to` → `to_date`。另外 `gen` / `order_no` 用**可空整数** —— `0`（我辈 / 长子）和「没填」必须区分。

### 打包体积：asar 从 20.64 MB 砍到 0.32 MB

`sql.js` 的 npm 包默认带 debug 版（5.5 MB ×2）、asm.js 版（1.3 MB ×3）、和 3 个 zip 包（5 MB）—— 合计 21 MB，占 asar 的 98%。
`build.files` 里用 `!` 排除掉，只留 `sql-wasm.js` + `sql-wasm.wasm`。

另外 `asarUnpack` 只放行 `sql-wasm.wasm`，让 WASM 以独立文件躺在磁盘上，绕开「从 asar 读二进制」的边界情况。

## 六、环境坑（本机实测，踩过就知道）

| 症状 | 原因 | 处理 |
|---|---|---|
| 一启动就报 `Cannot read properties of undefined`，且报错栈写着 **Node.js vXX** | 会话里设了 `ELECTRON_RUN_AS_NODE=1`，Electron 退化成纯 Node | `scripts/launch.js` 在 spawn 前清掉；npm 脚本已走它 |
| **窗口永远不出现**，没有任何报错（假死） | ESM 主入口下，Electron 要等**入口模块顶层求值全部结束**才发 `ready`；入口里顶层 `await` 等窗口 → 死锁 | 入口顶层不写 `await`，用 `.then()` 触发起步 |
| 满屏 `GPU process isn't usable` 然后退出 | 本机 GPU 进程不稳定 | 默认已关硬件加速（软件渲染）；`GENOGRAM_HW_ACCEL=1` 开回 |
| 应用启动「卡死」不响应 | 主进程错误框是**阻塞式**的，会一直等点击 | 排障时 `GENOGRAM_NO_DIALOG=1` + `GENOGRAM_DEBUG=1` |

排障开关：`GENOGRAM_DEBUG` / `GENOGRAM_NO_DIALOG` / `GENOGRAM_HW_ACCEL` / `GENOGRAM_DATA_DIR` / `GENOGRAM_BOOT_LOG` / `GENOGRAM_SELFTEST`。
